# AVI SalesConnect development instructions

- Treat [docs/SRS.md](docs/SRS.md) as the permanent, complete specification and execution baseline. Explicit later user instructions take precedence; record approved changes and decisions. Do not silently simplify, remove or defer any approved Phase 1 module, including tenders or expenses.
- Before changing code, read [progress](docs/PROGRESS.md), [roadmap](docs/ROADMAP.md), [architecture and decisions](docs/DECISIONS.md), [schema](docs/schema.md), [permissions](docs/permissions.md), [routes](docs/routes.md), [backlog](docs/backlog.md), [acceptance matrix](docs/acceptance-matrix.md) and [runbooks](docs/runbooks.md), plus relevant portions of the SRS. Inspect existing migrations and tests. The original prompt is retained verbatim in SRS.md; requirements.md is a legacy identical copy, not an independent authority.
- Complete and verify Milestone 1's security gate before implementing further functional milestones. Existing later work is not evidence that the gate passed. Work on independent foundation tasks while external verification is blocked; record exact blockers and never represent simulated tests as hosted evidence.
- Follow the SRS modular architecture, tenant isolation, active membership, least privilege, MFA, command boundaries, idempotency, append-only audit and private file requirements. Define schema, constraints and rollback/forward recovery before migrations. Use synthetic data only in fixtures. Never commit secrets or real personal/business data. Do not make unauthorized hosted changes or deploy.
- Keep requirement and acceptance statuses evidence-based. Run relevant tests and security checks; disclose failures and unverified gates. Update the schema, permissions, decisions, roadmap, acceptance matrix and runbooks as applicable.
- At the end of every development session update [docs/PROGRESS.md](docs/PROGRESS.md) with date, changes, test commands and results, current milestone, outstanding risks/blockers, decisions and concrete next steps. Preserve enough context for a fresh session without resupplying the specification.
